# AI-Powered Medical Data Preprocessing Agent

### From Messy Clinical Records to Reliable Time-Series Intelligence

Companion project for the PyCon Kenya 2026 talk **"From Messy Data to Clean Insights:
Building AI-Powered Data Preprocessing Agents with Python."**

An agent takes a deliberately messy synthetic hospital admission dataset and turns it into
a validated, model-ready hourly clinical time series. It plans its own work from a data
profile, executes deterministic pandas tools, checks each result against postconditions
declared in advance, repairs what it can, and **halts when it cannot**.

> An AI agent should not clean data by improvising. It should reason about the problem,
> execute controlled Python transformations, validate the results against conditions
> declared in advance, and leave an audit trail a human can check.

## Quick start

```bash
pip install -r requirements.txt

python run_pipeline.py                      # full pipeline end to end, ~7 seconds
python -m pytest tests/ -v                  # 29 regression tests
streamlit run visualization/dashboard.py    # reviewer dashboard
jupyter notebook Medical_AI_Preprocessing_Agent.ipynb
```

`run_pipeline.py` exits non-zero if any validation assertion fails, so it can gate CI
directly. No API key is required — the default planner is deterministic and offline.

## What the pipeline does

```
raw CSV (1,000 event rows, 24 columns, 7 defect classes)
    │
    ├─ PROFILE          160 kB of data  →  1.5 kB of description
    ├─ PLAN             8 tools selected, each justified from the profile
    │
    ├─ remove_duplicates        100 exact duplicates removed, row indices logged
    ├─ standardise_datetimes    4 spellings → 1; mis-parsed day-first dates avoided
    ├─ convert_units            °F → °C, mmol/L → mg/dL, suffixes stripped
    ├─ standardise_categories   61 free-text values → 22 canonical ones
    ├─ validate_ranges          implausible cells blanked, rows retained, each logged
    ├─ build_hourly_timeseries  900 event rows → ~4,700 hourly rows
    ├─ build_value_mask_decay   Value · Mask · Decay per channel
    └─ refine_missing_values    decay-gated refinement, observed cells untouched
    │
    └─ VALIDATE         52 assertions re-derived from the data, not from the audits
```

Artefacts written: `data/cleaned_medical_data.csv`,
`data/processed_hourly_timeseries.csv`, `reports/validation_report.json`,
`reports/cleaning_summary.html`, `reports/agent_trace.json`, and ten figures under
`outputs/figures/`.

## Two raw datasets

| File | Origin |
|---|---|
| `raw_hospital_admission_data.csv` | Generated by `preprocessing/synthetic_data.py`, calibrated to the published defect rates. **Default.** |
| `raw_hospital_admission_medical_data_original.csv` | The author's earlier hand-built file, kept for provenance. |

The original file has three generation defects that distort the demonstration:

1. **No duplicate rows at all** (`df.duplicated().sum() == 0`), so the deduplication step
   would show 0 → 0.
2. **Sentinel corruption at ~30% rather than 5%**, and it destroys the underlying value:
   `heart_rate == 300.0` (284 cells), `spo2 == 120.0` (284), `age == 150.0` (323),
   `mbp == "85 mmHg"` (282, always that exact string), `glucose == "6.6 mmol/L"` (339). MBP
   and glucose are therefore ~30% constant and unusable as signals.
3. **Day-first dates mis-parse silently** — `10/02/2026` is read as 2 October, so 48 of
   100 admissions get two different admission times and length of stay ranges from
   −6,997 h to +7,849 h.

Defect 3 is kept deliberately in the generated file, because it is the single best teaching
moment in the dataset. Defects 1 and 2 are fixed. Both files run through the identical
pipeline:

```bash
python run_pipeline.py --use-original-csv
```

or set `USE_ORIGINAL_CSV = True` in notebook §2.1.

**The original file makes the agent halt — on purpose.** Because of defect 2, range
validation strips more than half of three channels, the
`no_channel_lost_the_majority_of_its_observations` postcondition fails, no repair is
defined, and the run stops with exit code 1 rather than writing a dataset it cannot vouch
for:

```
spo2         595 ->  290   lost 51.3%
heart_rate   572 ->  288   lost 49.7%
age          665 ->  342   lost 48.6%
```

The agent reaches that verdict from the data alone, without being told which file it is
reading. It is the clearest demonstration in the project of why a quality gate has to be
paired with a coverage gate — see notebook §16.1.

## The representation: Value · Mask · Decay

Each channel is expanded into three aligned series.

| Series | Definition | Purpose |
|---|---|---|
| **Value** | last observation carried forward; population mean before the first observation | a complete numeric column |
| **Mask** | `1` observed, `0` imputed | preserves *what was actually measured* |
| **Decay** | `0.75 ** j`, `j` = hours since the last genuine observation | tells the model how much to believe the value |

Leading gaps use the population mean computed over observed cells only, so after
standardisation a neutral-filled cell is exactly `0` — the no-information point — while its
mask stays `0`. The pipeline verifies this empirically on every run rather than asserting it.

## DeepTSE-inspired refinement

Not a re-implementation of a published deep encoder — a reproduction of its *mechanism* in
a form that runs in under a second and can be read end to end:

```
x̂ = decay · LOCF  +  (1 − decay) · cross_channel_prediction        applied only where mask == 0
```

The refiner is trained by **self-supervised artificial masking**: observed cells are hidden,
the representation is rebuilt without them, and the model is fit where the context looks
like an imputed cell but the truth is known. Fitting on observed cells directly would let
the model copy its own target.

**Observed cells are never modified.** The rule is enforced in code and verified
independently by the validation agent.

### Honest benchmark

Held-out observations, block holdout (multi-hour outage — the realistic regime):

| | |
|---|---|
| Pooled error reduction vs LOCF | **+5.9%** |
| Channels improved | **5 of 8** |
| Best | mean BP +28%, systolic BP +17% |
| Worst | SpO₂ −8%, glucose −5% |

Under a random holdout of isolated cells the improvement drops to ~1%, because LOCF is
already near-optimal when the hidden cell is bracketed by measurements an hour away.

The conclusion is not "use DeepTSE refinement." It is **benchmark per channel and ship the
simpler method wherever it wins.**

## Validation

The validation agent re-derives every claim from the data rather than trusting the audits,
and writes 52 assertions to `reports/validation_report.json` plus a readable
`reports/cleaning_summary.html`.

This is not ceremonial. During development the independent check caught a defect the
agent's own postcondition missed: inverting the z-transform perturbed observed values by
~1e-4. The self-check worked on the standardised scale and saw nothing; the independent
check recomputed from the final table and failed two channels.

The report includes the **original row index of every dropped row**, so any claim can be
verified by opening the raw CSV at those line numbers:

```python
import json, pandas as pd
report = json.load(open("reports/validation_report.json"))
raw = pd.read_csv("data/raw_hospital_admission_data.csv", dtype=str)
for index in report["records"]["dropped_row_indices"][:5]:
    row = raw.iloc[index]
    print(index, (raw == row).all(axis=1).sum(), "identical rows")
```

## Using a live LLM planner

The pipeline runs fully offline by default. To let a language model plan:

```bash
pip install litellm
export GEMINI_API_KEY="..."      # or OPENAI_API_KEY / ANTHROPIC_API_KEY
python run_pipeline.py --llm
```

The model receives the tool catalogue and the ~1.5 kB profile and returns JSON. Its output
is validated **before anything runs**: unknown tool names are rejected and recorded as
concerns, and any ordering that violates a declared precondition is re-sorted. If nothing
usable survives, the rule-based planner takes over and the run continues.

Only the profile crosses the network. Patient rows never leave the machine.

## When *not* to use an agent

| Situation | Better approach |
|---|---|
| Fixed schema, known defects | A deterministic Python script |
| High-throughput ingestion | Compiled pipeline with schema validation |
| Strict data-residency rules | Local rule-based tooling only |
| Safety-critical automated action | Human in the loop, always |

The honest scope is **exploration**: new sources, unknown defects, the first hour of a
project. Once the schema stabilises, freeze the plan the agent produced into a script and
keep the validation layer.

## Relationship to the CodeAct reference implementation

Builds on the workflow in *Automating Data Preprocessing with AI Agents* (Barun Saha),
which uses a `CodeActAgent` to write and execute pandas locally under an import allow-list
and emit a JSON validation report the reader cross-checks against the raw file.

Inherited: the **validation report as audit trail**, and the **cross-check**.

Deliberately changed: the reference agent writes code; this one selects from a closed
catalogue.

| | CodeAct (reference) | Closed catalogue (this project) |
|---|---|---|
| Generality | Any pandas transformation | Only the eight declared tools |
| Review | Audit generated code afterwards | Inspect the plan before execution |
| Failure mode | Runtime error, or plausible wrong code | Rejected tool name |
| Best for | Exploration, novel defects | Clinical data, repeatable pipelines |

Neither is universally correct. Where a mistake means a wrong number in a patient's record,
the closed catalogue is the defensible default.

## Reproducibility

Every stochastic choice is seeded from `config.RANDOM_SEED` (2026). The generator
reproduces its CSV byte for byte, and `tests/test_pipeline.py` asserts it. The validation
report records the Python, pandas and NumPy versions, the platform and the seed.
